# 从 `7.1.4` 更新到 `7.2.0`


## 模型
如果你有任何 block model 符合以下情况：
 - 在已成型结构中覆盖了基础纹理（例如 EBF 中的流体仓染色），
 - 没有使用任何会设置该状态的内置 model 方法，

则需要在 MachineDefinition 中添加 `.modelProperty(GTMachineModelProperties.IS_FORMED, false)`。

## 范围输入/输出
现在可以在配方中使用：

- `.itemInputsRanged(..., min, max)`

- `.itemOutputsRanged(..., min, max)`

- `.fluidInputsRanged(..., min, max)`

- `.fluidOutputsRanged(..., min, max)`

输入或输出数量会在 min 到 max 之间闭区间随机抽取。

## 碎石机条件
过去，碎石机配方使用 `addData("fluidA", ...)` 方法。

现在它们通过 AdjacentFluidConditions 工作，并使用 `adjacentFluids(Fluid...)` 方法添加。参见[其他 condition builder 方法](https://github.com/GregTechCEu/GregTech-Modern/blob/1.20.1/src/main/java/com/gregtechceu/gtceu/integration/kjs/recipe/GTRecipeSchema.java#L894)。

类似地，过去带有相邻方块要求的配方现在需要使用 `adjacentBlocks(Block...)`，而不是 `addData("blockA")`。

也可以通过 `.adjacentFluidTag(ResourceLocation)` 和 `.adjacentBlockTag(ResourceLocation)` 使用带标签的流体与方块。

## Recipe Conditions（配方条件）
我们已经不再使用 RecipeCondition 上的 .serialize、.deserialize、.toNetwork 和 .fromNetwork 调用，现在只使用 recipeCondition 的 codec。
参见 [Recipe Conditions（配方条件）页面](../Recipes/Recipe-Conditions.md)。

## 原始泵
MV 输出仓不再是 Primitive Pump 的有效仓室，需要替换为 ULV`(new)` 或 LV 仓。

## 传送带与机器臂覆盖板
传送带覆盖板在放置为向管道输入物品时，可以选择分配模式：Priority（默认）、Round Robin 和 Round Robin with Restriction。

Round Robin with Priority 模式已改为 Round Robin with Restriction 模式。旧的 Round Robin with Priority 模式含义不清且无法正常工作。
新的 Round Robin with Restriction 模式会像 Round Robin 模式一样尝试均匀分配物品；但除非没有其他有效目的地，否则它会尽量*不*将物品送入 Restrictive Pipes。

机器臂覆盖板放在管道*出口*时，现在可以通过 Keep Exact 模式正确限制物品输出。
但是，用于将物品转移*进入*管道的机器臂仍然不能使用 Keep Exact 模式进行转移；它不会移动物品。
