# 从 `7.4.0` 更新到 `8.0.0`

## 新的数据保存/同步系统

新增了用于保存和同步对象字段的系统。迁移说明参见[此页面](../../Development/Data-Sync-System/Migrating-From-LDLib-SyncData.md)。

## 破坏性变更补充

以下迁移项会影响 addons、整合包脚本、存档数据或测试模板：

- `EnergyStack` 已删除；EU recipe content 不再保存为 `EnergyStack`。per-tick EU content 保存为 total EU/t 的 `Long` 值；一次性 `.inputEU()` / `.outputEU()` content 保存为 total EU 的 `Long` 值。
- KubeJS 的 `.inputEU(long)` / `.outputEU(long)` 会按传入 EU 值推导 tier；`.inputEU(voltage, amperage)` / `.outputEU(voltage, amperage)` 会写入 `voltage * amperage` 的 total EU，tier 由 voltage 推导。
- KubeJS 的 `.EUt(long)` 会临时切到 per-tick 语义并委托 input/output EU 写入；`.EUt(voltage, amperage)` 写入 `voltage * amperage` 的 total EU/t，tier 由 `Math.abs(voltage)` 推导。
- recipe tier 已从 EU content 中拆出，独立存储在 `GTRecipeDefinition` / `GTRecipe` 上；需要显式指定时请使用 `.tier(int)`。
- `RecipeAmperageEnergyContainer` 与 `BlockStateRecipeCapability` 已删除；请迁移到当前 RecipeCapability 和机器 trait 体系。
- `ChargerMachine` 已合并进 `BatteryBufferMachine`。用 `(info, tier, inventorySize, BatteryBufferMachine.AMPS_PER_BATTERY_CHARGER, 0)` 调用电池缓冲器构造函数，可获得与 charger machine 相同的行为。
- 同步存档 key 已从旧 LDLib sync data key 迁移为 `gtpm_sync_data`。自定义 `SavedData`、`ManagedSavedData`、`ManagedSyncBlockEntity` 或直接读取同步数据的代码需要改用新 key。
- GameTest 结构模板中的同步数据也已经迁移到 `gtpm_sync_data`；如果你的 GameTest 模板或断言依赖旧 key，需要同步更新。

## 机器重构第 1 部分：`MetaMachine` 与 `MetaMachineBlockEntity` 合并

为了简化机器系统并移除旧的、不必要的抽象，机器类的许多方面已被重构和修改。

- `MetaMachineBlockEntity`(MMBE) 类已被移除，`MetaMachine`(MM) 现在是 BlockEntity。
- MMBE 的大多数方法和属性已移动到 MM。
- `IMachineBlockEntity` 接口已被移除。请直接使用 `MetaMachineBlock`。
- 许多所有 block entities 通用的方法已移动到 `IGregtechBlockEntity` 接口。
- 机器实例创建函数的签名从 `(IMachineBlockEntity) -> MetaMachine` 改为 `(BlockEntityCreationInfo) -> MetaMachine`。

对 MMBE 的引用通常可以替换为对 MM 的引用：
```java
/////// OLD
if (level.getBlockEntity(getPos()) instanceof MetaMachineBlockEntity mmbe) {
    MetaMachine machine = mmbe.getMetaMachine();
    ...
}

////// NEW
if (level.getBlockEntity(getPos()) instanceof MetaMachine machine) {
    ...
}
```

机器构造函数中的 `IMachineBlockEntity holder` 参数已替换为 `BlockEntityCreationInfo info`：
```java
////// OLD
public MetaMachine(IMachineBlockEntity holder);
////// NEW
public MetaMachine(BlockEntityCreationInfo info);
```
为确保与默认 BlockEntity 方法保持一致，多个接口和类中的一些方法已重命名：

- `BlockPos getPipePos()` -> `BlockPos getBlockPos()`
- `Level getPipeLevel()` -> `Level getLevel()`
- `BlockPos getPos()` -> `BlockPos getBlockPos()`
- `BlockState getState()` -> `BlockState getBlockState()`
- `boolean isInvalid()` -> `boolean isRemoved()`
- `void markAsDirty()` -> `void markAsChanged()`

### 合并进 MetaMachine 的接口与行为

部分接口已被移除，其方法现在直接属于 MetaMachine 类。

- `IMachineLife` - 使用 `MetaMachine::onMachinePlaced` 和 `MetaMachine::onMachineDestroyed`。
- `IMachineModifyDrops` - 使用 `MetaMachine::modifyDrops`。
- `IInteractedMachine` - 使用 `MetaMachine::onUse` 和 `MetaMachine::onLeftClick`。

### 机器交互重构

处理机器交互的方法已经改变，现在都接收单个 `ExtendedUseOnContext` 参数。
机器交互已拆分为两个方法：`MetaMachine::onUse` 和 `MetaMachine::onUseWithItem`。

## 机器重构第 2 部分：新的机器 Trait 系统

新增了将 traits 与自定义行为附加到机器上的系统，许多机器接口和 traits 现在都使用这个新系统。

### 机器构造函数与 trait 初始化变更

为了简化机器实例创建，大量机器的构造函数已发生变化。此外，用于创建 trait 的方法也已移除，现在成为机器构造函数的一部分。

#### **所有机器**
- 将第一个构造函数参数 `IMachineBlockEntity holder` 替换为 `BlockEntityCreationInfo info`
#### `TieredEnergyMachine`
- 移除了 `createEnergyContainer` 方法
- 构造函数现在有一个可选的 `Supplier<NotifiableEnergyContainer>` 参数
#### `WorkableTieredMachine`
- 移除了 `createRecipeLogic`、`createImportItemHandler`、`createExportItemHandler`、`createImportFluidHandler`、`createExportFluidHandler` 方法
- 新增了一个构造函数：
    - `BlockEntityCreationInfo info`
    - `int tier`
    - `Supplier<RecipeLogic> recipeLogicSupplier` Recipe logic supplier，默认使用标准 `RecipeLogic` 类。
    - `int importSlots` 物品输入槽数量，默认值为机器默认 recipe type 的槽位数量。
    - `int exportSlots` 同上，但用于物品输出槽。
    - `int fluidImportSlots` 同上，但用于流体输入槽。
    - `int fluidExportSlots` 同上，但用于流体输出槽。
    - `Int2IntFunction tankScalingFunction` 流体槽容量缩放函数。
#### `WorkableMultiblockMachine`、`WorkableElectricMultiblockMachine` 与 `SteamWorkableMachine`
- 移除了 `createRecipeLogic` 方法
- 构造函数现在有一个可选的 `Supplier<RecipeLogic>` 参数，默认使用标准 `RecipeLogic` 类

### 新系统示例

#### 重要迁移说明：

Traits 必须通过对要附加的 trait 调用 `attachTrait(MachineTrait trait)`，直接附加到机器上。
过去，所有机器 traits 都以机器作为第一个参数来构造。
```java
/////// OLD
this.itemHandler = new NotifiableItemStackHandler(this, 0, IO.BOTH);

////// NEW
this.itemHandler = attachTrait(new NotifiableItemStackHandler(0, IO.BOTH))
```
迁移时，请从 machine trait 构造函数中移除 `this` 参数，并改为附加 trait。

新的 `AutoOutputTrait` 示例：

```java
public class CustomDrumMachine extends MetaMachine {

  protected final NotifiableFluidTank tank;
  public final AutoOutputTrait autoOutput;

  public DrumMachine(BlockEntityCreationInfo info, int capacity) {
    super(info);

    // Traits must be attached in the constructor.

    this.tank = attachTrait(new NotifiableFluidTank(1, capacity, IO.BOTH));

    // Registers an auto output trait that provides fluid output behaviour for the given fluid tank.
    this.autoOutput = attachTrait(AutoOutputTrait.ofFluids(tank));

    autoOutput.setFluidOutputDirection(Direction.DOWN);
    autoOutput.setFluidOutputDirectionValidator(d -> d == Direction.DOWN);
  }

  // Any code can query traits from a machine
  public static void queryTraits(MetaMachine machine) {

      // Returns a trait with the given type, or null.
      AutoOutputTrait autoOutputTrait = machine.getTraitHolder().getTrait(AutoOutputTrait.TYPE);

      Optional<RecipeLogic> recipeLogicOptional = machine.getTraitHolder().getTrait(RecipeLogic.TYPE);

      // Gets all traits with the specified type.
      List<NotifiableItemStackHandler> allItemStackHandlers = machine.getTraitHolder().getTraits(NotifiableItemStackHandler.TYPE);

  }
}
```

## Connected texture 重新实现
mod 的 connected texture 逻辑已在 GregTech Post Modern 本体中重新实现。
材质包、addons 和整合包需要稍微修改 connected texures 的纹理元数据文件。
下面是用于修复所有 MCMeta 文件的几个正则，请按顺序运行：

1. 匹配：`"ldlib":([\s\{]*)"connection"(:\s".*?")(?:,\s.*)?`
   替换为：`"gtpm":$1"connection_texture"$2`
2. 匹配：`\s*\},\s*"shimmer":\s*\{(\s*"bloom":.*)`
   替换为：`,$1`
3. 匹配：`(\{\s*)"shimmer":(\s*\{\s*"bloom":.*)`
   替换为：`$1"gtpm":$2`


## 其他变更

- `BlastingRecipeBuilder`、`CampfireRecipeBuilder`、`SmeltingRecipeBuilder` 和 `SmokingRecipeBuilder` 已合并进 `SimpleCookingRecipeBuilder`
    - 示例用法：`SimpleCookingRecipeBuilder.campfireCooking("cooking_chicken").input(new ItemStack(Items.CHICKEN)).output(new ItemStacks(Items.COOKED_CHICKEN)).cookingTime(100).experience(100).save(provider);`
- `GTFluidImpl` 已合并进 `GTFluid`，请使用 `GTFluid.Flowing` 和 `GTFluid.Source` 替代 `GTFluidImpl.Flowing` 和 `GTFluidImpl.Source`。
- Item behaviors 已移动到 `common/item/behavior`，部分 items 已从 `api/item` 移动到 `common/item`。
- `compat.minimap.surfaceRockProspectRange` 和 `compat.minimap.oreBlockProspectRange` 配置的最小值从 -1 改为 0。设为 0 时，该行为仍然禁用。
- 所有 materials 现在都存储在单一 registry 中，而不是每个 addon 一个 registry。将 `GTCEuAPI.materialManager` 的引用替换为 `GTRegistries.MATERIALS`。
- `ChargerMachine` 已合并进 `BatteryBufferMachine`。
  - 用以下参数调用电池缓冲器构造函数，可获得与 charger machine 相同的行为：`(info, tier, inventorySize, BatteryBufferMachine.AMPS_PER_BATTERY_CHARGER, 0)`
- Jade provider 代码已重构。用于特定机器类型的 jade providers 请使用 `MachineInfoProvider` 类，用于特定机器 trait 的 providers 请使用 `MachineTraitProvider`。
- `GTUtil.getMoltenFluid(Material)` 已移动到 `Material.getHotFluid()`。
- `ICopyable::copyConfig` 现在会直接修改传入的 `CompoundTag`，而不是返回一个新的。
