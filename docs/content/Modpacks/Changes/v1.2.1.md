# 从 `1.2.0` 更新到 `1.2.1`


## 自定义线圈

`coilMaterial` 函数现在使用 supplier，而不是直接接收 material。

```js
// Before:
.coilMaterial(GTMaterials.get('infinity'))

// After:
.coilMaterial(() => GTMaterials.get('infinity'))
```


## Recipe Modifiers（配方修饰器）

如果你的机器使用了自定义 recipe modifier，其语法有小幅变化。

现在可以应用多个 recipe modifier，因此更容易声明复杂的 modifier 链。
尤其是支持并行仓的多方块，现在需要用不同方式声明：

```js
// Before:
.recipeModifier(GTRecipeModifiers.PARALLEL_HATCH.apply(OverclockingLogic.PERFECT_OVERCLOCK, GTRecipeModifiers.ELECTRIC_OVERCLOCK))

// After:
.recipeModifiers([GTRecipeModifiers.PARALLEL_HATCH, GTRecipeModifiers.ELECTRIC_OVERCLOCK.apply(OverclockingLogic.PERFECT_OVERCLOCK)])
```
Recipe modifiers 必须作为 JavaScript 数组提供，因为 Rhino 会将其转译为 varargs（```RecipeModifier...```）值，而 ```.recipeModifiers()``` 方法接收的正是这种输入。如果不以数组形式提供，Rhino 会抛出异常并导致 Minecraft 崩溃。

## 基岩矿脉

基岩矿脉不再自动生成。
现在它们完全由整合包开发者定义，并且比旧系统更灵活。


```js
GTCEuServerEvents.oreVeins(event => {
    event.add('kubejs:my_custom_bedrock_vein', vein => {
        // ...
    })
    event.modify('kubejs:other_custom_vein', vein => {
        // ...
    })
    event.remove('kubejs:other_custom_vein')
})
```

关于如何使用 add 和 modify 事件的文档会随后补充。
目前请参考源代码中的 [`BedrockOreDefinition.Builder`](https://github.com/GregTechCEu/GregTech-Modern/blob/1.20.1/src/main/java/com/gregtechceu/gtceu/api/data/worldgen/bedrockore/BedrockOreDefinition.java#L117) 类。
